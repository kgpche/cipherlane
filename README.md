# cipherlane · 密道

**局域网端到端加密传输**，两种方式任选：

- **设备直发**（局域网 AirDrop）：一个 IP = 一台终端，每台设备有名字和几何头像。在线设备列表里点选目标，直接发文件或文本——对方接受即收，**全程无需传递链接**。密钥由 X25519 在双方浏览器内派生，永不明文过网。
- **链接模式**：生成 `#密钥` 链接经微信/邮件等方式发出。适合跨网段，或想要"服务器也完全零知识"的场景。

即使在明文 HTTP 的局域网里，内容也全程 AES-256-GCM 加密——中转服务器只见密文。

```
发送方浏览器/CLI                      局域网（HTTP 明文可被嗅探）              接收方浏览器/CLI
┌─────────────┐   设备发现/X25519公钥  ┌──────────────┐                     ┌─────────────┐
│ 选目标设备   │ ◀─────────────────▶ │  哑中继服务器  │ ◀────────────────▶ │ 在线列表被选中 │
│ ECDH 派生密钥 │     （只见公钥）      │  只见密文与流量 │    （只见公钥）      │ ECDH 派生密钥 │
│ AES-GCM 加密 │ ──── 密文分片 ────▶ │  邀请/中转/背压 │ ──── 密文分片 ────▶ │ AES-GCM 解密 │
└─────────────┘                     └──────────────┘                     └─────────────┘
     房间密钥 = SHA-256( X25519 双方私钥协商 ‖ 双方公钥 ‖ 房间号 )，两侧独立算出、一致
```

## 快速开始

```bash
node server.js            # 或 npm start；默认端口 7777，可用 PORT= 环境变量改
```

启动后打印局域网地址（如 `http://192.168.1.117:7777`）：

- **设备直发**：任意设备浏览器打开该地址 → 首页改好你的名字 → 在线设备里点选目标 → 拖入文件 / 粘贴文本 → 对方页面上弹卡片，点"接受"即收
- **链接模式**：不选设备直接拖入文件或点"加密发送文本" → 把生成的链接发给对方
- **接收**：设备直发会弹邀请卡片（含解密后的文件名/大小）；链接模式打开链接后点"开始接收并保存"

**页面任意位置 `Ctrl+V` 直接发送**：粘贴截图/文件立即发送，粘贴文本时已选设备则直接发、未选则填入文本框。

无浏览器的机器用 CLI（与浏览器完全互通，CLI 直发用 node 原生 X25519）：

```bash
node cli.mjs devices --server http://192.168.1.117:7777        # 查看在线设备
node cli.mjs send big.zip --to 192.168.1.50 --server http://... # 定向直发（无需传链接）
node cli.mjs send-text '一段密文内容' --to 192.168.1.50          # 定向发文本
node cli.mjs listen --yes -o ~/downloads --server http://...    # 常驻接收端（可被直发）
node cli.mjs send big.zip --server http://...                   # 链接模式：打印接收链接
node cli.mjs recv 'http://.../#ROOM.KEY' [-o 保存路径]           # 链接模式接收
```

## 安全模型

| 威胁                     | 防护                                                                 |
| ------------------------ | -------------------------------------------------------------------- |
| 局域网嗅探（明文 HTTP）  | 内容、文件名、类型全部 AES-256-GCM 加密，密文分片独立验签             |
| 运行服务器的人（链接模式）| 零知识：随机密钥经 URL `#fragment` 点对点传递，永不到达服务器          |
| 运行服务器的人（设备直发）| 房间密钥由 X25519 协商派生，服务器只见公钥与密文，事后翻日志无法解密   |
| 链接被无关者拿到         | 房间号 10 位 base62（约 59.6 bit）不可枚举；分片顺序一次性消费        |
| 直发邀请被第三方截获     | 邀请需持设备 secret 领取；预览（文件名/大小）本身也是密文              |
| 传输中被篡改             | GCM 认证标签逐分片校验，改 1 比特即报错；邀请预览验签失败自动拒绝      |
| 冒充发送方投毒           | 投递分片需持有随机 room token（仅发送方内存中有）                     |
| 小阶点/无效公钥攻击      | X25519 共享密钥全零即拒绝（RFC 7748 要求）                            |
| 房间滥用占内存           | 单房间背压窗口 64 分片/64MB，全局 256MB，空闲自动回收                  |

**已知边界（如实说明）**：

- **设备直发无法防服务器主动 MITM**：设备公钥由服务器分发，恶意服务器理论上可调包公钥冒充接收方。防"被动嗅探/被动翻日志"成立，防"主动欺骗"不成立——极高安全需求请用链接模式（密钥带外传递）。这与 AirDrop 等无带外验证的方案是同一取舍
- 设备名称与在线状态对服务器及局域网内打开页面的用户可见——这是"设备发现"的固有代价
- 接收不支持断点续传：分片顺序消费，刷新页面需发送方重发
- 纯 JS 降级路径约 10–20 MB/s（每 1MiB 分片独立加解密）；X25519 为 BigInt 实现，每次传输约 2 次标量乘（毫秒级）
- 恶意丢弃流量属于 DoS，可检测（传输卡住/报错）但无法防止
- 同一 IP 多个浏览器同时在线时，设备条目以后注册者为准（一个 IP = 一台终端）

**技术上如何做到 http 下也能加密**：浏览器 `crypto.subtle` 只在安全上下文（https/localhost）存在。本项目自带纯 JS 实现——非安全上下文自动降级：AES-256-GCM（`public/aesgcm.js`）、SHA-256（`public/sha256.js`）、X25519（`public/x25519.js`，BigInt + RFC 7748 Montgomery 阶梯）；localhost/https 下 AES 走原生 WebCrypto。纯 JS 与 node:crypto 原生逐字节一致（有测试）。需要 BigInt（Chrome 67+ / Safari 14+ / Firefox 68+）。

## 目录结构

```
cipherlane/
├── server.js           # 零依赖中继服务器：房间 + 设备在线 + 邀请（Node 内置模块 only）
├── cli.mjs             # 命令行：devices / 定向发送 / listen 常驻接收 / 链接收发
├── public/
│   ├── index.html      # 单页应用（设备网格 · 几何头像 · 邀请卡片）
│   ├── app.js          # 收发逻辑 + 双加密路径 + X25519 身份
│   ├── aesgcm.js       # 纯 JS AES-256-GCM（http 降级路径）
│   ├── sha256.js       # 纯 JS SHA-256（密钥派生 KDF）
│   ├── x25519.js       # 纯 JS X25519（设备直发密钥协商）
│   └── style.css
└── test/
    ├── aesgcm.test.mjs     # S-box 标准向量、GHASH 交叉、0B~1MiB 逐字节比对
    ├── sha256.test.mjs     # FIPS 180-4 向量 + 500 组随机 vs node 原生
    ├── x25519.test.mjs     # RFC 7748 向量 + 200 组随机 vs node ECDH 双向
    └── protocol.test.mjs   # 起真实 server：在线/邀请/定向传输/拒绝/上限全链路
```

## 测试

```bash
npm test    # 加密核心（4 套）+ 协议全链路（真实 server，含 X25519 双实现派生一致性）
```

协议与 CLI 端到端已验证：浏览器↔CLI、CLI↔CLI 定向文件/文本传输逐字节一致（含 3MB+ 多分片、拒绝路径、邀请上限、同 IP 设备轮换）。
