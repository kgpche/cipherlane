# cipherlane · 密道

**局域网端到端加密传输**：一个链接即可收发文件或文本。即使在明文 HTTP 的局域网里，内容也全程 AES-256-GCM 加密 —— 中转服务器是零知识的。

```
发送方浏览器/CLI                     局域网（HTTP 明文可被嗅探）              接收方浏览器/CLI
┌─────────────┐    密文分片     ┌──────────────┐     密文分片    ┌─────────────┐
│ 生成密钥 K   │ ─────────────▶ │  哑中继服务器  │ ─────────────▶ │ 从链接取回 K  │
│ AES-GCM 加密 │   (只有密文)    │  只见密文与流量 │    (只有密文)   │ AES-GCM 解密 │
└─────────────┘                 └──────────────┘                └─────────────┘
        └────────────── 接收链接: http://ip:7777/#房间号.密钥 ──────────────┘
                          （密钥在 #fragment 里，浏览器规范保证永不发给服务器）
```

## 快速开始

```bash
node server.js            # 或 npm start；默认端口 7777，可用 PORT= 环境变量改
```

启动后打印局域网地址（如 `http://192.168.1.117:7777`）：

- **发送**：任意设备浏览器打开该地址 → 拖入文件或输入文本 → 把生成的链接发给对方
- **接收**：打开链接 → 查看文件信息 → 点击“开始接收并保存”

无浏览器的机器可用 CLI（与浏览器互通）：

```bash
node cli.mjs send big.zip --server http://192.168.1.117:7777   # 打印接收链接
node cli.mjs send-text '一段密文内容' --server http://...        # 发文本
node cli.mjs recv 'http://.../#ROOM.KEY' [-o 保存路径]           # 接收
```

## 安全模型

| 威胁                     | 防护                                                                 |
| ------------------------ | -------------------------------------------------------------------- |
| 局域网嗅探（明文 HTTP）  | 内容、文件名、类型全部 AES-256-GCM 加密，密文分片独立验签             |
| 运行服务器的人           | 零知识：密钥经 URL `#fragment` 点对点传递，永不到达服务器             |
| 链接被无关者拿到         | 房间号 10 位 base62（约 59.6 bit）不可枚举；分片顺序一次性消费        |
| 传输中被篡改             | GCM 认证标签逐分片校验，改 1 比特即报错                                |
| 冒充发送方投毒           | 投递分片需持有随机 room token（仅发送方内存中有）                     |
| 房间滥用占内存           | 单房间背压窗口 64 分片/64MB，全局 256MB，15 分钟空闲自动回收          |

**技术上如何做到 http 下也能加密**：浏览器 `crypto.subtle` 只在安全上下文（https/localhost）存在。本项目的 `public/aesgcm.js` 提供纯 JS 的 AES-256-GCM 实现，非安全上下文自动降级使用；localhost/https 下自动用原生 WebCrypto（更快）。两条路径输出与 Node 原生逐字节一致（有测试）。

已知边界（设计取舍）：

- 接收不支持断点续传：分片顺序消费，刷新页面需发送方重发
- 纯 JS 降级路径约 10–20 MB/s（每 1MiB 分片独立加解密）
- 恶意丢弃流量属于 DoS，可检测（传输卡住/报错）但无法防止
- 服务器能看到密文大小、时间与 IP —— 流量分析不在防护范围

## 目录结构

```
cipherlane/
├── server.js           # 零依赖中继服务器（Node 内置模块 only）
├── cli.mjs             # 命令行收发（node:crypto 原生加密）
├── public/
│   ├── index.html      # 单页应用
│   ├── app.js          # 收发逻辑 + 双加密路径
│   ├── aesgcm.js       # 纯 JS AES-256-GCM（http 降级路径）
│   └── style.css
└── test/
    └── aesgcm.test.mjs # 与 node 原生逐字节比对 + 篡改/错密钥检测
```

## 测试

```bash
npm test    # 加密核心：S-box 标准向量、GHASH 双实现交叉验证、0B~1MiB 逐字节比对、篡改检测
```

协议层（建房/投递/长轮询/背压/一次性消费）与 CLI 端到端（8MB 随机文件 + 文本）已验证逐字节一致。
